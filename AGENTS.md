# AGENTS.md -- Human Datastream Portfolio

Personal portfolio at `jonathanlloyd.me`, styled as a sci-fi "Human Datastream" dashboard. Astro 7 site (Vite 8 / Rust compiler) served by a Cloudflare Worker with static assets (atlas decision 0160, PR A; before it, Cloudflare Pages). The Worker renders `/` per request from the live data (PR B); every other page is prerendered. Read-only display surface for personal data (health, activity, GitHub, reading, location). All widgets are imported from `@j0nathan-ll0yd/web/production` (the Design System package, consumed from GitHub Packages) -- this repo contains no widget source code.

## Commands

```bash
pnpm install                      # exact pnpm version comes from packageManager (corepack)
pnpm dev                          # localhost:4321
pnpm build                        # production build (reads data/*.json)
pnpm preview                      # preview the production output
pnpm run test:build               # Vitest build-output tests (SEO, JSON-LD, images)
pnpm run test:visual              # Playwright visual regression in Docker (arm64-native, CI-parity)
pnpm run test:visual:update       # regenerate baselines in Docker (the only sanctioned path)
pnpm run validate:build-fixtures  # Ajv validation of data/*.json against DS schemas
pnpm run generate:fixtures        # regenerate test/fixtures/build-data/*.json
pnpm run fetch:images             # download images from CloudFront to public/images/
node scripts/measure-ssr.mjs --base <version-url>  # plan Step 6.10: renders, TTFB, X-SSR-Data (Access token from .env.local)
```

Deploy: push to `main` -> GitHub Actions (`deploy.yml`) -> `pnpm build` -> `pnpm exec wrangler deploy --config workers/rate-limiter/wrangler.jsonc` (the `human-datastream-rate-limiter` Worker, which hosts the developer API's `ClientRateLimitWindow` Durable Object; it deploys first and fails the job on error) -> `pnpm exec wrangler deploy` -> the `human-datastream` Worker. The site Worker reaches the class through a `script_name` binding (added by the facade PR, #395, after the `v2` delete applied: Cloudflare error 10061 refuses a `deleted_classes` migration in the same deploy as any binding) and must never implement a Durable Object itself: Cloudflare generates no Version URL for a Worker that does (developers.cloudflare.com/workers/configuration/previews/, Limitations), and every PR preview needs one. `tests/unit/worker-entry.test.ts` fails if `src/worker.ts` exports anything but its default. A PR runs `preview-deploy.yml`: `wrangler versions upload` (a version, never a deployment) and, once Version URLs are on, a Cloudflare Access check through the CI service token. The Worker serves `jonathanlloyd.me` through the Workers Route `jonathanlloyd.me/*` (cut over 2026-10-14). That route lives in Cloudflare, not in `wrangler.jsonc`, and is set to fail open. Identify it by pattern and script, never by id: a dashboard edit (or any route replacement) recreates the route object with a new id. Never declare it in the config: a deploy that declares routes would replace it and reset fail-open, so `tests/unit/worker-routing.test.ts` fails if `routes` returns to the config. Rollback and re-creation: `docs/decision-0160/cutover-rehearsal-runbook.md`.

`src/worker.ts` is the Worker entry: it reproduces the Pages routing (middleware on every response, Pages route matching, asset-plane 405s). `src/lib/edge/` holds the middleware, the CloudFront proxy factory and the one header-policy module; the code routes are on-demand endpoints under `src/pages/` (`prerender = false`). `src/` holds only page/layout/route logic. Widgets, tokens, and runtime scripts all live in the Design System and are consumed via the `@j0nathan-ll0yd/*` packages.

**Audit layout (atlas decision 0111, phase 2b).** Every piece of audit code lives under one `audits/` root, declared in atlas `audits/audits.yaml`'s `layouts:` block and read by atlas check A19 for lane recognition. A check runner filename carries its catalog check id, so the ID-to-file mapping is spelled rather than remembered: `audits/checks/<id>-<name>.mjs` (`b2-llms.mjs`, `b6-check-analytics.mjs`, `b7-check-headers.mjs`). Code with no check id keeps an unprefixed name: shared helpers in `audits/lib/`, the B2 rule catalog in `audits/specs/`, runner-consumed golden files in `audits/fixtures/`, known-answer suites in `audits/__tests__/`, vendored XSDs in `audits/vendor/`, and the three lane-infrastructure scripts (`probe-suppression.mjs`, `preflight-egress.sh`, `healthchecks-ping.sh`) at the `audits/` root. Runtime code never moves here: `src/` (the Worker entry, its routes and `src/lib/edge/`) stays where Astro and the Worker route it. Renaming or relocating a runner requires the matching `runner:`/`test:` edit in atlas `audits/audits.yaml` in a paired PR.

## Data Flow

| Context         | Source                                                         | Mechanism                                                             |
| --------------- | -------------------------------------------------------------- | --------------------------------------------------------------------- |
| Request-time    | Workers KV `focus` + `fragments:<build>` (binding `PAGE`); CloudFront `/dashboard.json` without the binding | `readPublished()` in `src/lib/composed/published.ts`; `readComposed()` in `src/lib/composed/read.ts` (rollback) |
| Build-time      | `@j0nathan-ll0yd/copy` (identity only; no data)                | `loadDashboardData()`, both renders of `/`                            |
| Test fixtures   | `@j0nathan-ll0yd/fixtures/generated/<domain>/<variation>.json` | Playwright CloudFront route interception (`tests/visual/fixtures.ts`) |
| Client-side     | CloudFront                                                     | `@j0nathan-ll0yd/web/runtime/live-data.ts` after page load            |
| Polling         | CloudFront JSON                                                | PollEngine (30s fast, 120s slow), never cached by the service worker  |
| WebSocket       | API Gateway                                                    | Adaptive fallback when WS unavailable                                 |

**`/` is precomposed as the data changes, like llms.txt, and the live site supplies the composer (atlas decision 0160, PR B; owner decisions 2026-10-16; spec `openspec/specs/dashboard-ssr`).** Each build ships its composer (`src/lib/composed/compose.ts`, the Astro Container API in Node, never in the Worker) as a public static asset at `/_ssr/composer-<build>.mjs`, and `/version.json` names it with its sha256 and the contract version (`scripts/write-version.mjs`). `scripts/lib/build-id.mjs` is the ONE build id for version.json, the composer and the Worker (`__SSR_BUILD_ID__`); never derive it anywhere else. A backend runner in mantle-LifegamesPortal fetches version.json, then the composer, checks the hash, imports it and calls `composeDashboard`, which reads the focus signal and the eight exports through the public gated CloudFront URLs with `src/lib/data-plane/loader.ts`, re-reads focus after rendering, and returns the `/dashboard.json` artifact the runner stores behind the gate (5-minute backstop). `scripts/build-composer.mjs` builds the composer with this site's own compile settings, because Astro hashes a scoped style by the component's path relative to the build root; `pnpm run test:oracle` proves its fragments equal the Container render, that every scope it emits is in `dist/client/index.html`, and that `composeDashboard` refuses under hiding, a shut gate, an unreadable focus and a focus change mid-render. `src/worker.ts` answers `GET /` with `renderDashboard` (`src/lib/data-plane/ssr-response.ts`): `readComposed` (`src/lib/composed/read.ts`) reads the artifact with `readGatedConcurrently` (`src/lib/edge/proxy.ts`: the focus probe and the artifact fetch in flight together inside one budget, the focus value deciding first, so a hiding or unreadable value aborts the fetch and cancels an arrived body unread; the admission rules, no-store, no last-known-good copy, no `waitUntil`); `checkArtifact` (`src/lib/composed/artifact.ts`) refuses a stale (older than 690,000 ms, `COMPOSED_MAX_AGE_MS`), future, wrong-schema, hiding or malformed artifact, and any artifact whose `composer.build` is not the Worker's own build, so a site deploy shows the data-free page until the runner composes with the new composer; the artifact is not authenticated (any bucket writer can replace it), so every fragment must also pass the markup allowlist in `src/lib/composed/fragment-policy.ts` (a strict tokenizer: allowlisted elements and attributes only, class tokens from `src/lib/composed/fragment-classes.ts` keyed by fragment, scoped-style hashes from the fragment's own slot, `aria-*` from a closed set, at most 24 attributes per element, `popover` only on the System Status tooltip, each `data-*` value in the grammar the client runtime parses (`data-book` is a closed schema because the Book modal writes fields into `innerHTML`), same-origin or allowlisted-host URLs (the one exception: the Reading card's `a.article-list-title` may name any https host in its exact DS shape, `ARTICLE_LINK`; owner decision pending), a `style` declaration grammar, one `div` root with no `style` or `popover` that keeps its slot root's first class and scoped-style hash and names only its kind, state and accent (`FRAGMENT_ROOT_CLASS_TOKENS`), plus Hydration's hidden carrier, at most 32 levels, no id shared across fragments or with the page, and an artifact of at most 128 KiB), checked once per artifact text per isolate, and the composer applies the same check before it publishes; `pnpm run test:oracle` fails when a render is refused, when a render uses a class token the allowlist lacks, or when the allowlist names an element, class token, `aria-*` name, `data-*` name or link host no render of its fragment uses, so a design-system change that emits new markup must widen the allowlist in a reviewed change; the Worker then splices the fragments into the prerendered data-free page, cut once per isolate (`src/lib/composed/shell.ts`). The Worker renders nothing. A hiding focus value, the gate shut over a visible one, or an unreadable focus answers the build's value-free page (`src/lib/composed/value-free.ts`: `scripts/build-composer.mjs --value-free` writes `dist/client/_ssr/value-free.json` in postbuild, one variant per hiding value plus the gate and the unreadable focus, no export value, a public request gets the 404 page) as `suppressed` or `unavailable`; any other miss answers the data-free page as `fallback`; the 3 s ceiling (D2) also answers `fallback`; an exception answers the prerendered 500 page. Every data state answers 200 (D13) with no CDN storage (D3); the composed page is `Cache-Control: no-store` (`COMPOSED_CACHE_HEADERS`, so a browser never replays gated values from disk), the data-free and value-free pages `no-cache`. The dashboard read reserves no last-known-good window, and its two legs share the 2.5 s budget concurrently, so it takes about the slower leg, not the sum (soak 2026-10-17: the serial read timed out from colos far from CloudFront); the `ssr_render` line carries `focus_ms` and `artifact_ms`. The five proxy routes and the MCP server keep the serial probe-then-fetch. `HEAD /` answers from the data-free page and reads no data. Each answer writes one value-free `ssr_render` log line. The client runtime hands off without repainting: it repaints a card only from a strictly newer `generatedAt` (`src/lib/runtime/live-data.ts`), and sets `data-live-ready` on `<body>` after its first read.

**The build-time shell and the composer's facts (atlas decision 0164, Variant D, Phase 1).** Every `pnpm build` (`scripts/build-site.mjs`) runs `astro build`, cuts `dist/client/index.html` into `src/lib/composed/shell.generated.ts` (`scripts/build-shell.mjs`; gitignored, and excluded from eslint and dprint), runs `astro build` again so the Worker compiles that cut in (`src/lib/composed/compiled-shell.ts`, an `import.meta.glob` that finds nothing on a fresh checkout), then `build-shell.mjs --check` fails the build unless the second build shipped the same page and exactly one Worker module holds its cut. The cut: parse5 source offsets of the robots meta and the 13 `COMPOSED_FRAGMENT_IDS` roots, the Worker's own markers placed at them (`cutAt` in `src/lib/composed/shell.ts`), then `cutMarked`, so the build cut and the Worker cut derive slots, scopes, roots and ids one way. The page is sliced, never re-serialized. The module carries only `Content-Type`; the cache policy, `X-SSR-Data` and the security headers are set at serve time. `tests/build/shell-cut.test.ts` is the gate: the module is this build's (sha256 of the page), the pieces with the original slot contents rebuild the page byte for byte, and the shell equals the Worker's HTMLRewriter cut of the same page (run in Miniflare through wrangler's own dependency).  The composer's artifact body and each value-free page now carry `facts` (`WireFacts` in `src/lib/composed/artifact.ts`): what the Worker's `checkFragments` reads from the fragments, as plain arrays; the composer runs that same check before it returns, and `checkArtifact` ignores the field, so `COMPOSER_CONTRACT` stays 1. A `hiding` refusal names its mode (`{ok: false, refusal: 'hiding', currentFocus}`), so the runner publishes that mode's value-free page; the other refusals carry their word alone. `src/lib/composed/published.ts` defines the two Workers KV values the backend will publish (`focus`, `fragments:<build>`), and the composer exports `publishedEntry` to encode the second.

**`GET /` reads the published page data from Workers KV (atlas decision 0164, Variant D, Phase 3; spec `openspec/specs/dashboard-ssr`).** With the `PAGE` binding (`wrangler.jsonc`, namespace `human-datastream-page`, shared by production and the previews) and a compiled shell of the Worker's own build, `src/worker.ts` passes `published` to `renderDashboard`, and `attemptPublished` (`src/lib/data-plane/ssr-response.ts`) calls `readPublished` (`src/lib/composed/published.ts`): `focus` (`cacheTtl: 30`) and `fragments:<build>` (`getWithMetadata`) requested together, `focus` judged first (hiding: that value's value-free page; missing, malformed, older than 690 s, more than 300 s ahead or a failed read: the unreadable value-free page; in both the fragments value is never parsed, inspected, spliced or logged), then the fragments judged in order (metadata build, age, 512 KiB in UTF-8 bytes, shape, `fitsShell` against the compiled shell) and spliced into the compiled shell, `no-store`. Closed-set reasons: `focus-missing`, `focus-shape`, `focus-stale`, `focus-future`, `focus-error`, `fragments-missing`, `fragments-build`, `fragments-stale`, `fragments-future`, `fragments-oversize`, `fragments-shape`, `fragments-error`, `shell-misfit:<detail>`, logged as `artifact: published:<reason>`. The Worker does not run the allowlist on this path: it trusts the KV writer (the LP runner) and the composer's own check. Every `ssr_render` line carries `isolate_first` (the soak's cold marker) and `read_path`; a published answer adds `focus_kv_ms`, `fragments_kv_ms`, `focus_age_ms` and `fragments_age_ms`. Without the binding the Worker serves `/` from `/dashboard.json` as before (the rollback until Phase 4). The test seams (`X-SSR-Data-Plane: fixture`, or `DATA_PLANE_BASE`, on a preview or loopback host) read the same two values over HTTP from three files (`src/lib/data-plane/published-seam.ts`, names in `published-files.ts`): the committed `tests/fixtures/composed/kv-*.json`, or the local data plane (`tests/data-plane/server.ts`), which answers them as the backend would write them, so the visual and behavioral suites drive the published read. Profiling: `node scripts/cpu-bench/seed-kv.mjs` seeds the local namespace, then `PLANE=none node scripts/cpu-bench/profile.mjs <label> <warm> 100` profiles the production configuration.

**The data-free page (atlas decision 0160, PR 0a; spec `openspec/specs/dashboard-shell`).** `src/pages/index.astro` stays prerendered as `dist/client/index.html`: the budget fallback, the `HEAD /` answer and the rollback target for every later 0160 change (D9); there is no fixture rollback. Both renders share `src/layouts/DashboardHome.astro`. `loadDashboardData()` returns only the authored identity content (`src/lib/identity-profile.ts`: name, title, bio and links from `identity.person`, tagline and terminal from the `profile` namespace of `@j0nathan-ll0yd/copy`), the System Status rows with the no-reading mark, and the mirrored cover paths for Bookshelf `localCovers` (listed at build time, `src/lib/book-cover-mirror.ts`, because the Worker has no filesystem). On the data-free page every live widget renders `state="loading"`: its skeleton, `data-ssr-state="loading"` and a `<noscript>` note. The client runtime fills each card through the design-system updaters (`@j0nathan-ll0yd/web` 4.1), with the export's freshness: `live` up to its registry `audit.warn` age, `stale` beyond it with an absolute "as of" time (`exportFreshness`). A failed first read renders each card that export feeds `unavailable` (`renderWidgetUnavailable`); Night Summary follows the sleep export alone. Hydration draws its target bands in the browser, and a cover mirrored under `public/images/books/` (listed by its versioned contract path) loads from the same origin.

`@j0nathan-ll0yd/fixtures` is a **devDependency for tests only**. Two gates keep it out of production: `scripts/audit-fixtures.mjs` (prebuild) fails on a direct import under `src/` (and any reappearing `functions/`) and on hand-baked fixture JSON (Invariant I2); the `forbid-fixtures` Vite plugin (`scripts/vite-forbid-fixtures.mjs`, in `astro.config.mjs`) fails the build when ANY module in the production graph resolves to the package, directly or through another module or package. Its self-test is `tests/unit/forbid-fixtures.test.ts`. Tests that need populated widgets serve raw fixtures from `@j0nathan-ll0yd/fixtures/generated/` by CloudFront route interception, a path no production module reaches. There is no build-time fixture variation (`FIXTURE_VARIATION` is gone).

## Conventions

- **URLs answer 200 with no redirect**: `trailingSlash: 'never'` plus `build.format: 'file'` in `astro.config.mjs`, so `/privacy` builds as `dist/client/privacy.html` and `/offline` as `dist/client/offline.html`. Cloudflare serves `x.html` at `/x` with a 200 and redirects `/x.html` and `/x/` to `/x` with a 308. Pages answered 308 natively (measured on the PR #356 preview); Workers `html_handling` answers 307, so `scripts/generate-static-plane-rules.mjs` writes one 308 `_redirects` rule per form (`scripts/lib/redirects.mjs`), which runs before `html_handling`. A doubled slash (`/privacy//`) still meets the 307. A directory index (`x/index.html`) is served only at `/x/`, so `/x` would redirect; that was the production defect this convention fixes. `Dashboard.astro` derives the canonical URL and `og:url` from `Astro.url.pathname` with the `.html` / `/index.html` suffix stripped, because the `file` format puts the output file name in the build-time pathname. `tests/build/canonical-urls.test.ts` is the gate: it fails when a page builds as a directory index, or when a sitemap URL, canonical URL, `og:url`, internal link or JSON-LD URL has a trailing slash, names a `.html` file, or resolves to a directory index. Link to `/privacy`, never `/privacy/`.
- **Server-render test seams never reach production** (atlas decision 0160, PR B). The Worker variable `DATA_PLANE_BASE` points the render at a fixture data plane (local and CI suites write it to `dist/server/.dev.vars` after the build; postbuild deletes that file). `SSR_FAULT_INJECTION=1` enables the Step 6.10 headers `X-SSR-Fault` (`slow:<ms>`, `stall`, `status:<code>`, `suppress`, `focus-stall`) and `X-SSR-Clock` (a fixed render clock for visual baselines), and only for a `*.workers.dev` or loopback host (`src/lib/data-plane/faults.ts`). The PR preview upload sets it; `deploy.yml` runs `scripts/check-deploy-vars.mjs` before `wrangler deploy` and fails when either variable is set.
- **Two response planes on Workers, one header policy** (atlas decision 0160, PR A): the static-asset plane serves a file without running the Worker and applies `_headers`/`_redirects` only; the Worker runs for every path in `wrangler.jsonc` `run_worker_first` and for every path that matches no file. `src/lib/edge/security-headers.ts` is the ONE source: `scripts/generate-static-plane-rules.mjs` (postbuild) writes `dist/client/_headers` from it (replacing the adapter's immutable `/_astro/*` rule), and `src/lib/edge/middleware.ts` sets the same headers on Worker responses. `run_worker_first` lists exactly the code routes (`src/lib/edge/routes.ts` `EDGE_ROUTES`) and the paths with a middleware-only header (`HEADER_OVERRIDE_PATHS`); `tests/unit/worker-routing.test.ts` pins the list, the single compatibility date and flag set, `workers_dev: false` and `preview_urls: true` (on since owner gate G3; Access guards the Version URLs, and `scripts/check-worker-access-scope.mjs` must pass before the cutover, because an Access destination of type `worker` would also gate production), and fails if a `functions/` directory reappears (a Worker ignores it silently). `src/worker.ts` keeps the Pages behaviors Astro lacks: `Access-Control-Allow-Origin: *` and no-store 404s on asset-plane responses, an empty 405 for a non-GET on a page, trailing-slash route matching, and no CSP trio on the code-free prefixes `public/_routes.json` excluded. The adapter's Worker banner (`globalThis.process ??= {}`) leaks into client chunks; `scripts/vite-client-no-process-banner.mjs` clears it for the `client` environment and `tests/build/worker-output.test.ts` gates it. `astro.config.mjs` sets `security.checkOrigin: false` (Pages had no origin check; Astro's answered CSP reports with 403), `session: false` (no KV binding) and `imageService: 'compile'` (no Images binding). Build output: `dist/client/` (assets) and `dist/server/` (Worker, generated `wrangler.json`); resolve paths through `scripts/lib/build-paths.mjs`. Parity with Pages: `node scripts/worker-parity.mjs --candidate <url>` (plan Step 3.6).
- **No email address in clear in built HTML** (atlas decision 0158: obfuscation stays; since decision 0160 the Worker serves the site and Cloudflare's zone Email Address Obfuscation no longer rewrites it). Render any copy string that names an address with `src/lib/email/ObfuscatedText.astro` (`text`, `fallbackHref` = `EMAIL_FALLBACK_PATH`, `fallbackText` from copy) and load `EMAIL_DECODE_SCRIPT` (`public/js/email-decode.js`) once on that page. Each address becomes an XOR-encoded `data-email` link (cfemail style, `src/lib/email/obfuscate.ts`); without JavaScript it is a real link to the contact page, except on `/contact` itself, which links to `SECURITY_TXT_PATH` (`/.well-known/security.txt` publishes the address under RFC 9116). Three gates: `scripts/check-no-clear-email.mjs` (postbuild) fails on any address or `mailto:` in `dist/client/**/*.html`, except the organization's contact alias (copy `identity.organization.contactEmail`, a purpose-made revocable address, owner rulings 2026-10-24) inside the JSON-LD block, where the Organization and Person nodes name it; `tests/behavioral/email-obfuscation.spec.ts` checks the link with JavaScript on and off; `tests/smoke/home.smoke.ts` checks the SERVED bytes of `/privacy` and `/contact` after each deploy with the same detector (`findClearEmails`). Non-HTML outputs keep the clear address on purpose: `/.well-known/security.txt` (RFC 9116), text and Markdown.
- **No hardcoded values**: all colors, spacing, and typography come from `@j0nathan-ll0yd/tokens` `var()` custom properties.
- **No new widgets here**: never create `src/components/*.astro`; widgets belong in the Design System.
- **Raw scripts are ES2017 (SYNTAX rule)**: `<script is:inline>` bodies and any `public/js/*.js` are served raw (never transpiled by Vite), so their syntax floor is **ES2017** -- `const`/`let`, arrow functions, template literals, and `async`/`await` are all allowed. The site's real browser floor (service workers, PWA, canvas islands) is well above ES5, and async/await has had universal browser support since 2017. Avoid post-ES2017 syntax that lacks universal support. Bundled module scripts (processed by Vite) may use any modern syntax. **Enforced for `public/js/**/*.{js,mjs,cjs}`** by `pnpm run lint` (CI `lint` job, pre-push): `eslint.config.mjs` parses those files with espree at `ecmaVersion: 2017` (`sourceType: 'script'`; `.mjs` files are modules), so `?.`, `??`, object spread, class fields and top-level `await` are parse errors; `no-undef`, `no-unused-vars` and `no-empty` run too (an unused catch binding and an empty `catch` are allowed), with browser globals (service-worker globals for `sw-purge.js`). `tests/unit/public-js-floor.test.ts` pins that config. `<script is:inline>` bodies in `.astro` are not covered by this lint; the CSP rule keeps them out. This rule governs SYNTAX only and is independent of the CSP externalization rule below (CSP dictates _where_ scripts load, not what syntax they use).
- **Externalize inline scripts (CSP rule)**: all inline scripts live in `public/js/` for CSP compliance (10 page scripts: `card-reveal`, `clock`, `email-decode`, `leaflet-lazy`, `sa-loader`, `sa-stub`, `scroll-depth`, `sw-register`, `webmcp` (generated, loaded first and deferred), `social-click-track`; `book-modal` left with the native `<dialog>` migration in #86). `public/js/sw-purge.js` is not a page script: Workbox `importScripts` loads it into the service worker. Atlas audit A12 item 7 aligns any DECLARED `zod` specifier to `VERIFIED_ZOD_VERSION`, but it is an alignment rule and not a mandate: this repo declares no `zod` of its own (every zod 4 importer, the package included, resolves `4.6.7`; the one other copy is `3.25.76` under the dev-only `chromium-bidi` (`^3.24.1`, via `pa11y-ci` and `@lhci/cli`), which no 4.x override can satisfy), so it owes A12 nothing and must NOT add one to "comply".
  - **Sidecars ship but are NOT `exports` subpaths.** `.sha256` classifies INDETERMINATE under the export-surface rule and declaring one would poison that package's own surface verdict. Resolve a sidecar relative to the tier's reference module URL (`new URL('reference.mjs.sha256', new URL(import.meta.resolve('@j0nathan-ll0yd/estate-contracts/<tier>')))`), take the FIRST of the two whitespace-separated fields, and assert the two-field format -- an `awk '{print $1}'` one-liner rewrote one to a bare hash once and broke it for every consumer.
  - **The `covers-conformance` CI job now installs.** It used to run on node builtins with no registry dependency; that property was traded deliberately, because a stale local copy of a cross-repo rule passes green while enforcing a rule the estate has moved past, whereas a registry outage fails loudly and is retryable.
- **Every audit check step publishes a measurement channel** -- atlas decisions 0083, 0107, 0122. Each check step in `.github/workflows/audit-web.yml` is `continue-on-error: true`, so a check that runs, reaches nothing, and exits nonzero leaves `job.status` at `success` and pings a GREEN Healthchecks tile. `measured` is the only signal that separates a transport-dark run from a healthy one. Six rules, all gated:
  - **The count is artifacts held and judged**, never a finding count. A check that fetched three artifacts and failed all three measured 3. A check that reached none of them measured 0. Only the second is darkness. Suppressed counts as MEASURED -- the probe answered and the lane stood down deliberately, and an overdue suppression is a finding, which is also measured.
  - **`audits/lib/measurement.mjs` is the one writer**, reached through `report(checkId, findings, measured)` in `audits/lib/http.mjs`. The third argument is REQUIRED: forgetting it is a `TypeError` at the exit rather than a silently empty channel. `audits/__tests__/measurement.test.ts` reds on a two-argument call site anywhere under `audits/checks/`.
  - **The tier aggregates by records, not by a sum.** Each tier's `Healthchecks.io ping` step forwards `MEASURED_STEPS`, one `<step-id>|<outcome>|<measured>[|<reason>][|until=<YYYY-MM-DD>]` line per check step, and `audits/healthchecks-ping.sh` wedges the tier when ANY step claims `0`. A sum would let one dark check hide behind healthy siblings. Rung order is load-bearing: the measured rungs precede the `JOB_STATUS` case, because an unmeasured lane's job status reads `success`.
  - **A step that cannot count says so, with a reason.** `n/a` for a third-party tool run whose verdict is its own exit code (`smoke`, `lhci`, `pa11y` -- they hold no artifact set, and a number there would mean something different from what it means everywhere else). `lychee` left that set: lychee only fetches, and `audits/checks/b5-lychee.mjs` judges its JSON report and publishes the links it held an answer for. A connection refused before any HTTP exchange is UNMEASURED, never a pass and never a site failure, because the runner egress floor answers every host off its allowlists with a TCP reset (issue #148, weekly run 38428346533: 15 refusals over 6 hosts, all 200 from open egress). An unmeasured-only run is `indeterminate`, so the managed issue keeps its state, and the reconciler posts the run's note (the refused links, the reason, the counts) on the open issue once per run. Consequence, chosen deliberately: while any linked host sits off the runner allowlists, B5 never goes wholly green, so its managed issue stays open as the standing declaration of that blind spot, and a real broken link arrives as a note headed `B5 FAILING` on it rather than as a reopen. `deferred` for a step that could claim but is blocked on an external action. No step is deferred today: `llms_cache_rules` was, and now publishes its real count (a run that reads nothing publishes `0` and wedges the tier). An UNREASONED declaration wedges, so the opt-out cannot become a quiet escape hatch.
  - **A DEFERRAL EXPIRES; A NOT-APPLICABLE DOES NOT.** `n/a` is structural -- a tool run holds no artifact set and no owner action changes that, so it is permanent and carries no date. `deferred` is temporal by its own definition, so it carries `until=<YYYY-MM-DD>` as a trailing field and `audits/healthchecks-ping.sh` wedges the tier PAST that day (not on it), and on an undated, unreasoned or non-calendar one. Without the date the two declarations behave identically and the record written to make a gap VISIBLE is what makes it INDEFINITE: `llms_cache_rules` (then deferred) produced a green job, no managed issue and no wedge on run 34164468115 while all five Cloudflare reads returned 403 -- the same shape as run 34086625518, the receipt decision 0122 opened with. The marker is self-describing and position-independent so a prose reason may contain `|`, and so a record without one parses exactly as it did before; that is also what keeps atlas A19 green while the hub adopts the same rung on its own cadence (`parseMeasuredStepRecords` folds every trailing field into one reason string, so `until=` reads as reason text there).
  - **Every record must bind to its OWN step, and `audits/__tests__/audit-web-workflow.test.ts` is the blocking gate.** A record's `measured` field must be that step's `${{ steps.<id>.outputs.measured }}` or a reasoned `n/a`/`deferred` declaration -- nothing else, including an integer literal. A literal is the falsified-record shape: the step's real count is never read, the constant can never be `0`, and the step goes permanently dark while the tier pings green. Atlas A19 catches it as `step-measurement-misbound`, but A19 is report-only, hub-side and daily, and **merging here deploys production**, so the blocking gate has to be local. The suite reds on a MISSING record and on a FALSIFIED one alike.
- **B6 is two daily steps, one per arm, each with its own count** -- owner decision 2026-10-13 (option A). `analytics_beacons` runs `audits/checks/b6-check-analytics.mjs --arm beacons` and publishes the beacons it observed (0-4). `analytics_ingestion` runs `--arm ingestion` (synthetic event -> `/simple/events` proxy -> SA collector -> Stats API) and publishes `1` when the Stats API answered and the arm judged ingestion, pass or fail (an HTTP 401 is an answer). It publishes `0` when the arm held no answer: the Stats API was UNMEASURED, `SA_API_KEY` is missing, or every read threw (`noAnswer`, for example `CERT_HAS_EXPIRED` or `ECONNABORTED`, which still files #149 as `failure`). `0` wedges the daily tile the same day. A persistent UNMEASURED never escalates #149 itself (review item M5); the red tile is that escalation. One step used to publish the beacon count whatever happened to ingestion, so a dark Stats API pinged green. Both steps feed ONE managed-issue bucket, `analytics` (issue #149, matched by its unchanged title), through their own `issue_outcome`: any `failure` files, both `success` closes, and an UNMEASURED or SKIPPED ingestion arm reads `indeterminate` and leaves the issue unchanged. Never route either step's raw `outcome` to the reconciler, and never default a missing `issue_outcome`. `--arm` is required; a step without it crashes before measuring, wedges the tile, and files #149 as `failure` (a wiring defect, not an analytics regression). Gates: `audits/__tests__/b6-check-analytics.test.ts`, `audits/__tests__/audit-web-workflow.test.ts`, `audits/__tests__/measurement.test.ts`.
- **The rule catalog is probed for two different things, and neither substitutes for the other** -- ADR 0011 follow-up (b), atlas decision 0129 C6. `audits/specs/**/*.rule.json` pins each quoted clause to a `pinnedAt` -- on `cites` for a conformance rule, on `derivedFrom` for a local one -- which `rule.schema.json` constrains through `definitions.immutableUrl` to three IMMUTABLE shapes (a 40-hex commit-pinned `raw.githubusercontent.com` blob, an `rfc-editor.org` RFC text, a versioned `rssboard.org` archive). **There is no `spec` block and no `verification_url`.** The single shared `spec` object that carried both names was split into the two arms by the 0129 consumer round; `b2-check-spec-drift.mjs` exports `citation(rule)` (`rule.cites ?? rule.derivedFrom`) as the ONE accessor across both, and `derivedFrom` requires `pinnedAt`, `retrieved` and `content_sha256` whenever it carries a `quote`, so a quote on either arm is locatable, dated and digest-protected.
  - **`b2-check-spec-drift.mjs` asks "is the transcription still faithful?"** It re-fetches that pinned URL and asserts every quote segment still occurs in it, in order. Its offline integrity half (`audit:spec-integrity`) blocks every PR; its network half runs weekly. Because the target is frozen by construction, this check **cannot** see an upstream revision -- that is not a gap in it, it is the property its comparison depends on.
  - **`b2-check-spec-currency.mjs` asks "is the pinned clause still what the specification says today?"** Weekly, report-only, wired into no PR gate. For a commit-pinned GitHub source it compares the pinned blob against the same path on the default branch (`HEAD`) and reports the pinned commit, the current commit, both content digests, and whether each dependent citation `quote` still occurs in the CURRENT blob (`citation(rule).quote`; the field was called `spec.normative_quote` before the 0129 split and the old name survives only in historical prose). Severity is split on that last answer: a revision whose quotes survive is `warn` (exit 0, a prompt to re-read the surrounding prose), a quote that has GONE is `fail` -- `fail` is the only severity the managed-issue reconciler sees, so it is what makes a human look. The receipt: llms.txt shipped a v2 dated 2026-08-10 while this repo pinned 2026-07-30, the five normative Format bullets byte-identical, and nothing in the estate could tell.
  - RFC and RSS-archive sources are classified **not-applicable** and reported, never silently skipped -- a revision there becomes a new number at a new URL, so there is no current version at that identity. They are excluded from `measured` on purpose: counting them would let a total `raw.githubusercontent.com` outage publish a non-zero count and ping a green tile.
- **Install integrity doctor (`pnpm run doctor:install`)**: an install churn can leave a `node_modules/.bin/*` symlink dangling (under pnpm every `.bin` entry links into the content-addressed `node_modules/.pnpm/` store, so a pruned store or a cross-platform clobber from the Docker visual harness produces exactly this), surfacing later as a cryptic `command not found` mid-hook. The doctor runs first in `pre-push` and fails loud with the fix (`pnpm install --frozen-lockfile`, or `rm -rf node_modules && pnpm install --frozen-lockfile` -- a targeted rebuild does not repair it).
- **Formatting**: 2-space indent, UTF-8, LF line endings.

## Testing

- **Visual baselines:** regenerate only in Docker (`pnpm run test:visual:update`); host-rendered PNGs fail CI.
- **Canvas widgets use a deterministic test seam, not hidden pixels:** rAF + RNG defeats Playwright's `animations: 'disabled'`, but never hide a canvas via `visibility: hidden` in `screenshot.css` -- that masks regressions. Each canvas widget exposes a `window.__<widget>` seam (defined in its DS runtime init, e.g. `@j0nathan-ll0yd/web/runtime/heart-rate-init`) with `ready`, `seed(n)`, `freezeAt(ms|null)`, `step(frames)`, and `state()`. The seam is gated by BOTH `import.meta.env.MODE === 'test'` AND a `data-test="1"` ancestor, so it is `undefined` (dead-code-eliminated) in production. Reference: `#hrEcgCanvas` / `window.__hrEcg` (`tests/visual/heart-rate.spec.ts`). Seam-driven screenshots need a `--mode test` visual build.
- **Production smoke check (replaces the retired pixel-drift suite):** `tests/smoke/home.smoke.ts` (config `playwright.smoke.config.ts`, helpers `tests/smoke/fixtures.ts`) asserts the live site at `https://jonathanlloyd.me` actually hydrated -- HTTP 200, all widget containers present, `.is-loading` skeletons cleared, the bio terminal typed its content (the #50 CSP-blocked-hydration regression guard), the service worker registered, and no external-script CSP violation / chunk-load failure / unexpected console error. Runs on the self-hosted `[self-hosted, linux, arm64, playwright, cfedge]` lane (no Docker, no pixel baselines; `cfedge` because the fleet reaches CloudFront only from that egress lane) via `.github/workflows/smoke-check.yml` on `workflow_run` after `deploy.yml`; it is post-deploy and non-blocking (files a `smoke-failure` issue rather than blocking the deploy). Run locally with `pnpm run test:smoke`. The retired drift suite could not stay green against a live data stream and could not catch a blocked-hydration failure (the SSR shell renders at the correct pixels even when hydration is dead).

## Do Not

- Rely on post-ES2017 syntax in raw-served scripts (`public/js/*.js`, `<script is:inline>` bodies). ES2017 -- `const`/`let`, arrow functions, template literals, `async`/`await` -- is allowed; only avoid newer syntax that lacks universal browser support.
- Create new `src/components/*.astro` files or hand-edit CSS (everything comes from the DS).
- Import from relative `../lib/` or `../scripts/` paths instead of the `@j0nathan-ll0yd/*` namespace.
- Hardcode hex colors or pixel values.
- Bypass prebuild schema validation.
- Hand-edit `.contract-lock.json` (Husky + CI enforce it; regenerate via `scripts/generate-contract-lock.mjs`).
- Depend on a `@j0nathan-ll0yd/*` producer change that is not yet published to the registry -- publish a new version from the producer repo first, then bump the caret range / lockfile here (merging to `main` deploys production).
- Regenerate visual baselines outside Docker (`pnpm run test:visual:update` is the only sanctioned path; host PNGs fail CI).
- Use `npm` in this repo. It is a pnpm project (atlas decision 0032): `packageManager` pins `pnpm@11.13.0`, `pnpm-workspace.yaml` holds the overrides/peer/supply-chain settings, and an `npm install` here would write a foreign lockfile and shunt packages aside (`pnpm run doctor:install` reports it).
